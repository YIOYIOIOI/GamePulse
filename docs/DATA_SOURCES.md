# 数据来源与覆盖

## 接口

| 来源 | 接口 | 范围 |
|---|---|---|
| Steam 评论 | [IUserReviewsService/GetAppReviews](https://partner.steamgames.com/doc/webapi/IUserReviewsService) | 按创建时间倒序分页，全部语言、全部购买渠道，限定 UTC 时间范围；记录平台报告的匹配总数，用于核对是否收齐 |
| GitHub issue | [Search issues](https://docs.github.com/en/rest/search/search) | 关联仓库中在时间范围内有更新的公开 issue，排除 PR；搜索最多返回 1,000 条 |
| GitHub Release | 仓库 Releases 接口 | 版本号、标题、发布时间和发布说明链接 |
| 添加游戏时的查找 | Steam 商店搜索与 `appdetails`、GitHub 仓库接口 | 只用来确认 App ID 和仓库存在，不进入任何快照 |

全部是匿名公开接口，不需要密钥。抓取串行进行，带限速和重试。

## 添加游戏时的校验

- 只能添加 Steam 上类型为游戏或 DLC 的条目；原声音轨、视频、试玩版没有玩家评论，会被拒绝。
- GitHub 仓库可选，填写 `owner/name` 或仓库链接都可以，必须是公开仓库。
- 每次同步会把当时的游戏定义（App ID、名称、仓库）写进快照。之后修改仓库或移除游戏，不影响已有快照，离线重新计算也只用快照里的定义。

## 覆盖情况

每次同步结束后，「设置 → 数据源」会按游戏和来源列出采集条数和状态：

| 状态 | 含义 |
|---|---|
| 完整 | Steam：抓到了平台报告的全部评论，并读到了真实的末页；GitHub：分页走到了最后一页 |
| 部分 | 达到单次采集上限（每款游戏 6,000 条评论、4 页 issue、2 页 Release），或分页游标重复、数量与平台报告不一致 |
| 未关联 | 这款游戏没有关联 GitHub 仓库，不抓取 issue 和 Release |

只要有来源是「部分」，界面顶部就会显示「部分数据不完整」，并关闭依赖完整数据的判断：Steam 评论不完整时，不做 30 天变化和版本对比的显著性判断。字段校验不通过的记录进入隔离表，保留原因和原始位置。

## 没有覆盖的内容

- 评论和 issue 的内容是否属实没有逐条验证；来源真实不代表内容主张成立。
- Steam 评论的语言是评论者自己选的标签，可能与正文语言不一致，系统不改写这个标签。
- 没有接入游戏内部的安装、付费、留存和客服数据。
- 接口返回的是抓取当时的状态；评论或 issue 之后被编辑或删除，不会反映到已有快照里。
